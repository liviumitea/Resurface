# Resurface product backlog

Jira-ready draft, 23 October 2026. [Product Spec v0.2](https://alexadima.atlassian.net/wiki/spaces/~5ff74facd364960139d5a2ee/pages/688150/Product+Spec+v0.2) defines the initial scope. The existing app implements the P0 UI and local-first model; this backlog distinguishes completed code from unverified behavior. Do not mark an item done solely because a screen exists.

Priority: **P0** before external beta, **P1** for a durable and useful v1, **P2** after beta evidence. Create one Jira epic per section and one child story/task per numbered item. Each item below includes its acceptance gate.

Jira epics: [core loop](https://alexadima.atlassian.net/browse/SCRUM-23), [data safety](https://alexadima.atlassian.net/browse/SCRUM-25), [resurfacing](https://alexadima.atlassian.net/browse/SCRUM-24), [capture](https://alexadima.atlassian.net/browse/SCRUM-28), [pilot/release](https://alexadima.atlassian.net/browse/SCRUM-27), and [optional sync](https://alexadima.atlassian.net/browse/SCRUM-26). The initial 22 child tasks are SCRUM-29 through SCRUM-50; [SCRUM-51](https://alexadima.atlassian.net/browse/SCRUM-51) tracks a reflection-note bug, and six reviewed additions are SCRUM-52 through SCRUM-57 below. Existing architecture decisions remain in SCRUM-21 and SCRUM-22; they were not duplicated.

## Epic 1 — Reliable core loop (P0)

1. **Make local iOS and Android builds reproducible.** Fix the Expo-generated iOS script failure when the checkout path contains spaces; document and automate clean native regeneration. Gate: `npm run ios` works from `Proiect Alexandra`, Android builds from a clean checkout, and CI checks TypeScript, tests, and JS exports.
2. **Automate the lifecycle rules.** Use a controllable clock and database-level tests for save → due → Today selection → shown → response → next due, including daily cap, overdue order, local-day boundaries, daylight-saving changes, pause/archive/resume, and app restart. Gate: every rule in README has a passing automated test against the same queries/schema used by the app. *Status (SCRUM-32): done in `tests/lifecycle.test.ts` against `src/store.ts`, the same store code the app uses; reflection-note persistence for all three responses (SCRUM-51) is covered automatically, but SCRUM-51 still needs device verification.*
3. **Complete device acceptance on iOS and Android.** Run first-save onboarding, text/photo/OCR capture, search/edit/delete, all three reflection responses, app restart, and denied permissions on physical devices. Gate: recorded pass/fail results with OS/device versions; no P0 failures remain.
4. **Harden error and loading states.** Recover from permissions, OCR, storage, and notification errors without silent data loss or a stuck screen. Gate: each recoverable failure has a clear retry/fallback; fatal key/database failure never silently resets data.
5. **Accessibility and localization readiness.** Check VoiceOver/TalkBack order, labels, dynamic text, touch targets, contrast, keyboard use, and date/time formatting. Gate: the complete core loop is usable with screen readers and larger text. *Status (23 Oct 2026, code review + iOS simulator at the largest accessibility text size): muted text darkened to pass WCAG AA everywhere; roles/states/labels added (Library filter tabs, daily-cap radios, notification-text switch, headings, onboarding step); 44 pt minimum targets for chips, icon buttons and photo retry; fixed heights replaced by minimum heights; display titles capped with maxFontSizeMultiplier while body text scales fully; the Library page now scrolls as a whole. Today and Library verified at AX5. Still to do: a VoiceOver/TalkBack walk-through on devices, Android large-font check.*

## Epic 2 — Data durability and privacy (P0)

6. **Encrypted export.** Export insights, reflections, events, settings, and encrypted photos in a versioned, password-protected archive. Gate: no personal plaintext is left in shared or temporary files; export content and version are verified before presenting the share sheet. *Status (SCRUM-34/36, in progress): archive core done in `src/backup.ts` — version 1, scrypt (N=2^15, r=8, p=1) + AES-256-GCM with the whole header authenticated, photos re-encrypted under the backup password, strict validation of every record and cross-reference, and `replaceAllRows` restoring in one transaction (replace-only for v1; a forgotten password cannot be recovered). Covered by `tests/backup.test.ts`. Device glue (`createBackupFile`, `restoreBackup` in `src/storage.ts`) and Settings UI (password sheet, share sheet via expo-sharing, file picker via expo-document-picker, replace warning) are implemented but not yet run on a device. Still to verify on device: scrypt time under Hermes, share/pick on both platforms, large photo libraries (the whole archive is held in memory), and that photo paths survive app updates (they are stored as absolute URIs). New native modules require rebuilding the development client.* *iOS simulator acceptance, 23 Oct 2026 (Release build, iPhone 18 Pro, iOS 27): create backup, share sheet shows the file as Resurface Backup with Save to Files, saved file opens with the password and is rejected with a wrong one, cache copy deleted after sharing; restore asks to replace everything, picked copy deleted, wrong password refused, correct password replaced the data (an insight added after the backup was removed) and kept history. Password step takes about 10 s under Hermes (scrypt N=2^15). Android and physical devices still pending.* *Roadmap Milestone 1 (24 Oct 2026): export now fails closed — any missing or unreadable photo stops the backup before sharing with an itemized count; the user may explicitly choose an archive that records its omissions, and restoring it says so. Imports are bounded before any work: 128 MB archive cap (also enforced on export, so no unrestorable backup is ever made), scrypt ceiling 64 MiB (N≤2^16, r≤8, p=1), record-count caps, and the picked file's size is checked before reading.*
7. **Safe restore.** Import an archive into a staging area, authenticate and validate it, then commit atomically; show merge/replace consequences before changing existing data. Gate: wrong password, corrupt archive, duplicate IDs, and interrupted restore leave current data intact; a fresh installation restores images and history.
8. **Platform backup/key-loss review.** Verify iOS/Android uninstall, OS backup/restore, keychain/keystore behavior, device migration, and file protection. Gate: tested recovery expectations match onboarding/settings copy; no ciphertext is backed up without a recoverable key strategy.
9. **Privacy and deletion audit.** Inspect picker/OCR/cache copies, logs, notifications, analytics, and permanent deletion. Gate: no personal content leaves the device without explicit export; residual local copies and OS limitations are documented. *Status: code review done 23 Oct 2026, see README "Privacy and deletion review". Fixed: launch-time removal of picker/manipulator/document-picker plaintext caches and stale backup files; dismissal of delivered notifications for removed or seen insights or after insight text is turned off; Android `allowBackup` disabled. Device verification pending.*

## Epic 3 — Resurfacing and notifications (P0/P1)

10. **Notification reliability (P0).** Test scheduling, deep links, permission changes, foreground/background/terminated launches, time-zone and daylight-saving changes, edit/pause/archive/delete, and long absences. Gate: the app-only Today path always works; notifications do not duplicate, leak private text by default, or target removed insights.
11. **Timed pause and snooze (P1).** Let a user defer an insight until a chosen date without treating the deferral as a positive response. Gate: one pending event remains, history is preserved, and the reminder queue reconciles correctly. *Status: implemented 23 Oct 2026 — Snooze (1 week / 1 month / 3 months) on an active insight's detail screen, which also shows when it next resurfaces. `snoozeInsight` cancels the pending event (kept in history) and schedules one at the same stage; it records no response and reconciles reminders. Covered by three lifecycle tests; tried on the iOS simulator (Release build).*
12. **Richer reminder controls (P1).** Add day/time window and quiet-period controls only after observing beta needs. Gate: settings remain understandable and do not promise exact OS delivery times. *Status (SCRUM-40, 24 Oct 2026): opt-in extension implemented with the simple default intact: time presets beside the HH:MM field and optional quiet weekdays (Monday-first chips; all seven refused). Scheduling skips quiet days, keeps one reminder per day and re-applies the chosen time daily across daylight-saving changes. Six tests cover quiet days, DST in Europe/Bucharest, a time-zone change, and queue reconciliation through the production store. Settings copy states Today works with notifications off and times are approximate. Checked on the iOS simulator; delivery on devices remains SCRUM-38. Adaptive schedules deferred until pilot evidence.*

## Epic 4 — Easier capture and retrieval (P1)

13. **Share Sheet capture.** Accept text, links, and images from other apps on both platforms. Gate: shared content opens an editable draft, explicit Save is required, and cancellation leaves no persisted insight. *Status (SCRUM-41, 24 Oct 2026): slice 1 (text and links) implemented with expo-sharing's experimental share extension — shared text becomes the insight text, a lone link becomes the source, an editable draft opens, Save is explicit and cancel persists nothing; the app-group store is read and cleared immediately. Verified on the iOS 27 simulator by sharing from Safari. Slice 2 (images, same day): one shared photo opens on the photo step (keep as image or extract text); it is copied out of the app-group container into the app cache, the container copy is deleted, and it is encrypted only on Save; unreadable or oversized (>64 MB) photos show a recoverable message. Verified on the simulator by sharing from Photos: the encrypted file was written and neither plaintext copy remained. Android (`image/*` intent) builds in CI but is untested without a device. Signed device builds need the app group `group.app.resurface.mobile` registered with the Apple team (SCRUM-47).*
14. **Source attribution and favorites.** Add optional source metadata and a favorite flag with search/filter support. Gate: existing records migrate safely; neither field is required for capture. *Status (SCRUM-42, 24 Oct 2026): implemented as schema 3 — optional source (≤200 chars) at capture/edit, shown on detail and Library rows and included in search; a favorite star on detail with a Library favorites filter that combines with status, category and search; neither affects resurfacing. Backups with either are archive v3; older archives restore without them. Tests and iOS simulator check done.*
15. **OCR quality and fallback.** Test English/Romanian images, rotated/cropped images, poor light, and image-only fallback. Gate: editable OCR never replaces the original image and failures do not discard the draft. *Status (SCRUM-43/52, 24 Oct 2026): fixture set and results in `tests/fixtures/ocr/README.md` (EN/RO, rotated, low light, no text, 12 MP HEIC); all six have a usable outcome on macOS Vision and the HEIC was checked end to end on the iOS simulator. Extract text now appends instead of replacing typed text, Keep as image no longer clears it, reading can be stopped or retried, and saving shows preparing/encrypting progress with recoverable failure. On iOS, photos are prepared by a local ImageIO module (`modules/resurface-image`) that decodes at 2048 px with orientation applied; device latency is still unmeasured (SCRUM-52).*
16. **Library/history polish.** Improve empty states, search performance, image display, chronology, and reflection editing if pilot feedback supports it. Gate: migrated data and all lifecycle history remain accurate. *Status (SCRUM-44, 24 Oct 2026): sort by newest/oldest/recently resurfaced; encrypted photo thumbnails (memory-only, capped cache, icon fallback); result count; per-row resurfacing count and last date; history summary and date-time per exposure. Tested and checked on the iOS simulator; further polish waits for pilot feedback.*

## Epic 5 — Pilot, measurement, and release (P0/P1)

17. **Privacy-safe beta measurement (P0).** Define activation, shown, answer rate, and worth rate from content-free events; keep the denominator visible and document limitations. Gate: no insight/photo/reflection content is logged or transmitted; metrics match fixture data. *Status: `tests/metrics.test.ts` checks the Settings signals against fixture data (answer rate = answered / shown, worth rate = yes / answered, per the build plan) and that every counter is a known name plus a time with no personal content. The app now records when the worth question is asked, shown beside the rates. Revised 24 Oct 2026 (roadmap P0 #4): two milestones, both from content-free counters that survive deletion and shown in Settings with dates — **first-save activation** (`firstSaveAt`, Product Spec v0.2's activation) and **core loop completed** (`coreLoopAt`, first resurfacing seen after that save). Provisional pilot thresholds, per participant, to confirm with the pilot: first-save activation ≥80% within the first session day; core loop completed ≥60% within 7 days of first save; answer rate ≥30%; worth rate ≥50% over at least 20 answers; read alongside interviews; deleting an insight removes its history from the signals.*
18. **Pilot feedback and decision gate (P0).** Test with reflective users from the target persona; collect qualitative examples of usefulness and failure. Gate: a written go/no-go decision cites usage plus interviews, without claiming behavioral change from taps alone.
19. **Signed beta distribution (P0).** Configure bundle IDs, signing, store metadata, privacy disclosures, crash reporting without personal content, and TestFlight/Play internal testing. Gate: install/update on physical devices, verify encrypted data survives update, and document rollback.
20. **Dependency/security maintenance (P1).** Review compatible Expo/native updates and advisories, then upgrade with native regression tests. Gate: no forced framework downgrade, and build/test results are recorded. *Status (SCRUM-48, 24 Oct 2026): expo 57.0.31 and expo-notifications 57.0.24 applied (all SDK 57-aligned); 5 remaining high advisories are build-tool only (node-forge, zod inside @expo/cli), have no compatible fix, and are absent from the app bundles per source maps — documented in README. Native rebuild regression pending device acceptance.*

## Epic 6 — Optional cross-device future (P2, discovery first)

21. **Sync architecture decision.** Validate whether users need multi-device access after export/restore and pilot feedback. Compare device-only, user-controlled backup, and end-to-end encrypted sync. Gate: threat model, recovery design, cost, privacy obligations, and user value are agreed before backend work.
22. **End-to-end encrypted sync (conditional).** Only if item 21 is approved: build accounts, device enrollment, encrypted records/blobs, conflict resolution, key recovery, and deletion semantics. Gate: the server cannot read personal content; cross-device and lost-device recovery are tested. No backend is needed for the current device-only beta.

Out of scope until evidence changes the decision: generated advice, automatic insight extraction/tagging, social features, streaks, goals, mood tracking, and adaptive schedules.

## Product Spec v0.2 traceability notes

- The P0 `+` capture-type selector (Write / Take photo / Choose photo / Cancel) was added after auditing the spec on 23 October 2026. The full capture flow still needs device acceptance in SCRUM-31.
- SCRUM-33 (code complete, device acceptance pending): Today now has loading skeleton, ready, and recoverable error/“Try again” states (with a Library fallback); a stale request cannot overwrite a newer one, and a card is only marked shown once Today has loaded. The fatal storage screen offers a non-destructive retry. A missing database key next to an existing database now stops startup instead of generating a replacement key. Library load failures show a retryable message instead of an alert over stale results; a photo that cannot be decrypted shows a message with retry, and a missing photo file says so. The photo key has the same no-replacement guard when encrypted photos exist. Still to verify on device: skeleton/error rendering, retry after a forced query failure, the locked-device/key-unavailable path, Library retry, and the photo error/missing states.
- The spec's Account/Sign out/Delete account items are conditional on authentication. The current device-only beta has no account or backend; SCRUM-22 should record that architecture decision before account work is planned.
- The spec calls reminders “push”; the current implementation uses local notifications. SCRUM-38 covers delivery, privacy, and deep-link acceptance on real devices.
