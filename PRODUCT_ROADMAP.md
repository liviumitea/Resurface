# Resurface — private-build product roadmap

Reviewed 24 October 2026 against repository `main` through `0b56eb5`, the [Product Spec v0.2](https://alexadima.atlassian.net/wiki/spaces/~5ff74facd364960139d5a2ee/pages/688150/Product+Spec+v0.2), and the current [handoff](CLAUDE_HANDOFF.md). The owner does **not** want to publish yet. This plan is for making the app more complete and useful in private builds; it is not a store-submission checklist. The [backlog](PRODUCT_BACKLOG.md) retains existing Jira acceptance gates.

## What exists now

The device-only app covers the spec's capture → resurface → reflect loop: first-save onboarding; text, photo, OCR and incoming Share Sheet capture; Today, same-day revisit and reflection; a searchable Library with categories, source, favorites, sorting and photo thumbnails; insight lifecycle/history and snooze; local reminders with a preferred time and quiet weekdays; English/Romanian UI; SQLCipher data, AES-GCM photos, versioned encrypted backups, restore and a backup checkup. Screen components and flow hooks have been extracted from `App.tsx`. Draft privacy, help/recovery and store-privacy documents exist.

TypeScript and **82 automated tests passed locally on 24 October**. The tests cover scheduling, migrations, archive compatibility, categories, source/favorites, sharing payloads, localization, reminder rules and All-insights search. Individual flows were checked on an iOS 27 simulator Release build. This is implementation evidence, not proof of physical-device behavior. No backend or account is needed for the present product direction.

The previous feature-first roadmap's steps 1–6 have code implementations. Do not rebuild Library polish, incoming sharing, photo/OCR feedback, reminder controls, screen extraction or draft help/privacy documentation as if they were still missing. The All-insights Library feature and its accent-insensitive search are now implemented. The iOS smoke script's restore-warning step passed in three complete runs, and a native simulator backup/restore with photos passed on 25 October. Android runtime, OS notification delivery, screen-reader use and real-device performance are also unverified.

### 3. Make the next return understandable — implemented

Jira: [SCRUM-64](https://alexadima.atlassian.net/browse/SCRUM-64).

Implemented on 25 October 2026. Today has a "See what's coming up" link to an **Upcoming** screen: the next 20 active insights not already on Today, soonest first. Each row says "Due now · waiting for room in Today", "Later today", "Tomorrow" or "From {date}" by local calendar day, and the total is counted. A footer explains the daily cap and that reminders are approximate (time, quiet days, or off). Rows open Detail (with snooze), and Back returns to Upcoming. It is a separate screen, so Today never shows upcoming text unasked, and it is read-only: looking is not a resurfacing. Nothing is added to notifications. Four store/domain tests cover pause, resume, archive, snooze, a real showing, the daily cap, an empty queue, the limit, a time-zone change and the DST night. A Release build on the iOS 27 simulator was checked: the rows matched the stored schedule, snoozing from Detail moved the row on return, and the largest text size wrapped cleanly. The smoke script now opens Upcoming (18 steps, three consecutive passes). Physical-device acceptance is not done.

### 4. Make reflections maintainable — implemented

Jira: [SCRUM-62](https://alexadima.atlassian.net/browse/SCRUM-62).

Implemented on 26 October 2026. Each exposure in Insight Detail's history has **Add a note** / **Edit note**, with an inline editor and a confirmed **Remove note**. A note shows "Edited {date}", or "Added {date}" when written on a later day than the exposure. Only exposures the user actually saw take a note; responses, events and next due dates never change (changing a past answer remains out of scope). If a note was added from history before the user answered in Reflect, the answer's note is appended so the exposure keeps one note. Schema migration 4 adds `reflections.updatedAt`; archive version 4 is written only when some note was edited, so other backups stay readable by older builds, and v1–v3 archives restore as never edited. Counters `reflection_edited` and `reflection_removed` are content-free. Four store/backup tests cover add/edit/remove, restart, no extra exposure or answer, the unchanged due date, unseen events, the Reflect overlap and the v4/legacy archive round trip; the 0.1.0 migration test now expects the new column. On the iOS 27 simulator (Release build) the database migrated with all 8 insights intact; adding and editing a note showed the right labels with the due date and history unchanged; and the app's own backup was a v4 archive containing the edited note and its edit time. After the simulator was rebooted, that archive was restored natively: the note was first removed in the app (confirmation shown; due date and history unchanged), then Settings → Restore → document picker → password replaced the data, and the note came back with "Edited 26 Oct 2026", the same next date, history, source and category. The smoke script then passed 18/18 three times in a row.

### 5. Let saved photos be managed safely — implemented

Jira: [SCRUM-63](https://alexadima.atlassian.net/browse/SCRUM-63).

Implemented on 26 October 2026. Insight Detail has a **Photo** section: **View full screen** (also by tapping the photo; pinch to zoom, labelled Close, VoiceOver escape), **Add a photo** / **Replace photo** (camera or library; replacing asks first), **Read text from photo** and **Remove photo**. Read text puts the recognised text after the saved text in the edit form with a review note; nothing is stored until Save changes, Cancel discards it, and Stop deletes the temporary decrypted copy at once. A replacement is encrypted to a new `<insight id>-<uuid>.enc` file before a single conditional update points the insight at it; the old file is deleted only after that succeeds, and a failure removes the new file. The same conditional update refuses removal when the insight has no text (the button is also disabled with an explanation), and an edit that would clear the text of an insight without a photo is refused too, so overlapping changes can't leave an empty insight. At launch, files that an existing insight no longer refers to (an interrupted replacement) are removed; files named after no existing insight are never touched. Deleting an insight removes every file named after it. Counters `photo_added`, `photo_replaced`, `photo_removed` are content-free. Six store/domain tests cover add/replace/remove without changing schedule, history or notes; the photo-only and missing-insight refusals; overlapping edit/removal and two overlapping replacements; backups after replacement and removal; and which leftover files the launch sweep picks. On the iOS 27 simulator (Release build) a photo-only test insight was saved and: removal was disabled with its explanation; the viewer opened and closed; text was read into the edit form, Cancel left the insight unchanged and a later Edit started empty; saved text enabled removal; Replace wrote a new file and deleted the old one; Remove deleted the file and kept the text; Add wrote a new file; deleting the insight left the photo folder exactly as before the test with no plaintext copies in the cache. Backups are unchanged in format (no archive version change), so no new native restore round trip was run.

### 6. Recover interrupted capture drafts

Jira: [SCRUM-59](https://alexadima.atlassian.net/browse/SCRUM-59) text/metadata recovery, then [SCRUM-60](https://alexadima.atlassian.net/browse/SCRUM-60) encrypted draft photos and share conflicts.

Today, the capture form and incoming share draft live in memory; leaving the flow or an app interruption can lose work. Add an encrypted draft that survives app restart without becoming a saved insight or scheduling a resurface. Start with text/context/source/categories only and ship that; then, if still wanted, handle a draft photo as encrypted app-private data and clear its plaintext picker/share copies. Show **Resume draft / Discard draft** and avoid silently replacing one draft with incoming shared content. Gate: restart, interruption, cancel, Save and share-over-existing-draft cases neither lose an accepted draft nor leave orphaned plaintext/photo files; draft data is excluded from insight metrics and reminders.

### Owner request: keep an insight as a memory — implemented

Jira: [SCRUM-67](https://alexadima.atlassian.net/browse/SCRUM-67) (created by the owner on 26 October 2026, outside SCRUM-58).

Implemented on 26 October 2026. The capture screen, which every capture path reaches (text, photo, read text, incoming share), has a **Resurface this** switch, on by default and reset for each new capture. Off means "just keep it as a memory": the insight is saved in one transaction as `paused` with no event, so it never enters Today, takes no daily slot and gets no reminder, and the confirmation says it won't come back on its own. Paused insights are now labelled **Resurfacing off** / **Fără revenire** everywhere (Library tab and empty states, Detail), Detail explains what that means, and its button reads **Turn on resurfacing** / **Pornește revenirea**: the existing resume rule then creates exactly one stage-0 event due a day later, and repeated taps add nothing. Library rows that never resurfaced and are off say "Not set to resurface". After such a save the Library switches from the Active tab to All so the item is visible, and the notification permission prompt waits for the first save that will come back. No schema or archive change: backups already accept a paused insight without a pending event. Counter `insight_created_library_only` is content-free. Four tests cover no event and no Today/Upcoming/reminder over 200 days and restarts, the paused filter, categories and a photo-only item; one event a day after activation with no duplicates; the unchanged default; and a backup round trip in the same archive version. On the iOS 27 simulator (Release build, Romanian UI) a text insight was saved with the switch off: the switch text and the confirmation said it is kept as a memory; Detail showed "Fără revenire" with the explanation and **Pornește revenirea**; the Library's Fără revenire tab listed it as "Nu e programată să revină"; turning resurfacing on made it Activă with "Revine după 27 oct. 2026" (the next day); the test insight was then deleted. Not checked on the simulator: the switch to the All tab after Continue, the photo and incoming-share paths (they reach the same capture screen), and the first-save permission prompt (permission was already asked on this simulator).

## Not in this phase

No store publication, signing project, release date or public-beta claim is requested. Physical-device acceptance, signed distribution and pilot evidence remain later gates if the owner decides to distribute. Account/cloud sync, AI-generated advice, social features, streaks and adaptive resurfacing are not needed to make this private device-only app comprehensive. Possible later experiments—multiple photos, widgets, bulk Library actions or end-to-end encrypted sync—should follow use of the remaining core work above.
