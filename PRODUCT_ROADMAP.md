# Resurface — review and prioritized roadmap

Reviewed 24 October 2026 against repository `main` at `7956fd3`, [Product Spec v0.2](https://alexadima.atlassian.net/wiki/spaces/~5ff74facd364960139d5a2ee/pages/688150/Product+Spec+v0.2), and the [SCRUM Jira board](https://alexadima.atlassian.net/jira/software/projects/SCRUM/boards/1?filter=&groupBy=none). This is a plan and review, not an assertion that the release gates have passed. `CLAUDE_HANDOFF.md` has operating details; `PRODUCT_BACKLOG.md` has the existing issue-by-issue acceptance gates. Re-check both code and Jira before executing the plan because they may change.

## Current position

The device-only beta implements onboarding, text/photo/on-device OCR capture, Today and reflection, Library and lifecycle/history, snooze, local notifications, SQLCipher storage, AES-GCM photos, password-protected export/replace restore, and local content-free metrics. There is no account, backend, or sync. On 24 October, `npm run typecheck` and all 37 tests passed locally. The repository's CI includes iOS/Android JavaScript exports and an Android native debug build. The 23 October iOS 27 simulator Release-build checks exercised several flows, including text capture, backup/restore without photos, snooze, accessibility text sizing, and key-loss recovery; see `CLAUDE_HANDOFF.md` for exact evidence. Do not mistake those checks for physical-device acceptance.

The beta is **not ready for outside distribution**. No physical-device pass is recorded, Android runtime behavior is not accepted, photo-containing restore and notification delivery are unverified, and signing/privacy/store release work remains. Keep personal data on-device and keep sync conditional rather than adding a backend by default.

## Findings to resolve before external beta

1. **P0 — An export can be incomplete.** `src/storage.ts:createBackupFile` counts an unreadable/missing photo, drops a photo-only insight and its history, or strips the photo from a text insight, then still creates an archive. `App.tsx:shareBackup` warns only after the share sheet closes. Treat backup completeness as a safety property: fail closed by default; if partial export is ever allowed, show an explicit itemized pre-share choice and mark the archive incomplete. Test missing/unreadable images, image-only insights, and successful full photo round trips on both platforms. Related: [SCRUM-34](https://alexadima.atlassian.net/browse/SCRUM-34), [SCRUM-36](https://alexadima.atlassian.net/browse/SCRUM-36).
2. **P0 — Imported archives need resource limits.** `src/backup.ts` accepts KDF settings as high as N=2^20, r=16, p=4; scrypt's nominal memory at that N/r is about 2 GiB. The file and its photos are also read/parsed in memory without a size limit. Bound archive bytes, record/photo counts and total image bytes before deriving a key; use a practical KDF cost budget on target phones; reject oversized or unreasonable imports with a recoverable error. Retain forward compatibility deliberately, not by accepting unbounded work. Related: SCRUM-36 and [SCRUM-48](https://alexadima.atlassian.net/browse/SCRUM-48).
3. **P0 — Photo capture is too slow.** The 23 October iOS simulator measurement in `CLAUDE_HANDOFF.md` attributes 13–115 seconds to `ImageManipulator.manipulateAsync` for a library HEIC, despite later byte read/encryption/write taking under 50 ms combined. The 2048-pixel downscale reduced stored size, not the reported wait. Benchmark pick, decode, resize, JPEG encode, encryption, and DB commit independently on real devices. Compare the SDK 57 [contextual `ImageManipulator.manipulate` API](https://docs.expo.dev/versions/v57.0.0/sdk/imagemanipulator/) and picker compression/representation settings; choose by measured latency, quality, OCR legibility, and memory. Set and test an agreed photo-save latency target. Related: [SCRUM-31](https://alexadima.atlassian.net/browse/SCRUM-31), [SCRUM-43](https://alexadima.atlassian.net/browse/SCRUM-43).
4. **P0 — Define metrics consistently.** Product Spec v0.2 calls *first insight saved* the activation goal; `src/store.ts:getBetaMetrics` calls *save plus first resurfacing shown* activation. Keep both: `first_save_activation` and `first_resurfacing_seen`/`core_loop_completed`, with explicit participant and time-window denominators. Preserve content-free local counters; do not infer behavioral change from taps. Related: [SCRUM-46](https://alexadima.atlassian.net/browse/SCRUM-46), [SCRUM-45](https://alexadima.atlassian.net/browse/SCRUM-45).
5. **P0 — Finish evidence, not just code.** Physical iPhone and Android acceptance must cover first save, text/photo/OCR, all reflections, search/edit/delete, backup with photos, wrong password/corrupt archive, denied permissions, app restart/update, notification delivery/deep links/long absence, VoiceOver/TalkBack, and key/OS-backup behavior. Record device/OS, steps, results, failures, and fixes. No Jira issue should be marked Done only because its UI exists. Related: SCRUM-29, 31, 33, 35, 37, 38, 51.
6. **P0 — Keep docs and Jira truthful.** README previously said no export/backup despite the implemented v1 archive; this review updates that line but the user-facing copy still needs a final release audit. Jira currently shows nearly all new Resurface tasks as In Progress, even when `PRODUCT_BACKLOG.md` says code complete; split implemented/verified/blocked work and transition only after the stated acceptance gate. Also reconcile the old [Flutter task SCRUM-7](https://alexadima.atlassian.net/browse/SCRUM-7) with the actual Expo architecture decision, without deleting history.

## Delivery sequence

### Milestone 1 — Trustworthy core (next)

Fix backup completeness and import limits; measure and reduce photo-save time; separate first-save activation from core-loop completion; add failure/performance tests; correct user-facing backup/privacy copy. Gate: no known path to an apparently successful but silently incomplete backup, bounded import work, and an agreed photo-save latency target met on a real iPhone and Android phone. This milestone is more important than new feature work.

### Milestone 2 — Device acceptance and release safety

Complete the physical-device matrix above, including real notification behavior and full encrypted photo backup/restore. Review compatible dependency security updates without forcing Expo/React Native downgrades. Add signed TestFlight and Play internal builds, verify install/update keeps encrypted data, and prepare privacy disclosures, terms, support, and rollback guidance. Gate: all P0 failures fixed or explicitly accepted with user-visible limitations; no claim of completed acceptance based solely on simulator or CI results. Related: [SCRUM-47](https://alexadima.atlassian.net/browse/SCRUM-47), SCRUM-48.

### Milestone 3 — Small, instrumented pilot

Recruit reflective users from the target persona; observe first save and the first return, run short interviews about whether resurfacing was useful, and report first-save activation, return/core-loop completion, answer rate, worth rate, and question-answer denominator. Confirm or revise provisional thresholds in `PRODUCT_BACKLOG.md` before using them for a go/no-go decision. Store no personal content in telemetry. Gate: written decision supported by both usage and interviews, without claiming behavior change from self-report alone. Related: SCRUM-45/46.

### Milestone 4 — Evidence-led v1 improvements

If pilot capture friction is high, spike **Share-to-Resurface** for text/links/images, with an editable draft and explicit Save. Expo SDK 57 documents incoming sharing as [experimental, with an iOS caveat](https://docs.expo.dev/versions/v57.0.0/sdk/sharing/), so prototype on devices before committing to it. If retrieval friction is high, add optional source attribution and favorites, then consider categories (a future requirement in v0.2), Library/history polish, and Romanian/English localization. Add richer reminder windows only if users request them; preserve the simple app-only Today path. Related: SCRUM-40–44.

### Milestone 5 — Conditional cross-device future

Compare device-only plus encrypted export, user-controlled backup, and end-to-end encrypted sync after pilot feedback. Only build accounts/backend/sync if the need, threat model, key recovery, conflict resolution, deletion semantics, and operating cost justify it. A future server must not be able to read insight text, reflections, or photos. Related: [SCRUM-49](https://alexadima.atlassian.net/browse/SCRUM-49), [SCRUM-50](https://alexadima.atlassian.net/browse/SCRUM-50).

Do not prioritize generated advice, social features, streaks, goals, mood tracking, or adaptive schedules without new evidence; they are outside the current product thesis. The immediate next implementation task is backup fail-closed behavior and restore resource limits, followed by the photo-save benchmark.
